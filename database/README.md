# 内容采集与提炼器 - 数据库模块（SQLite V1）

> 仅覆盖“数据库模块”，不包含前端、抓取逻辑、摘要算法实现。

## 1. 数据库设计思路

### 目标
第一版支持：
1. 保存文章链接
2. 保存文章标题、作者、发布时间、来源
3. 保存原始正文
4. 保存清洗后的正文
5. 保存一句话摘要
6. 保存 3-7 条核心观点
7. 保存标签
8. 为短视频文本、文件内容预留扩展

### 核心设计原则
- **简单优先**：主表 `contents` 集中存储一篇内容的核心元数据与文本。
- **可扩展**：通过 `content_type` 和扩展字段（`extra_json`）支持未来新内容类型。
- **结构化与灵活并存**：
  - 结构化字段用于常用查询（标题、来源、发布时间、摘要等）。
  - `extra_json` 存放暂未稳定的扩展信息，减少频繁改表。
- **多值信息拆表**：核心观点与标签采用独立关系表，避免在主表里塞字符串数组。
- **可迁移性**：尽量使用 PostgreSQL 兼容语法/约束思路，便于后续迁移。

## 2. 表结构

### 2.1 `contents`（内容主表）
存储文章/短视频转写/文件解析后的统一内容实体。

### 2.2 `content_key_points`（核心观点表）
每篇内容 3-7 条核心观点，支持排序。

### 2.3 `tags`（标签表）
全局标签去重存储。

### 2.4 `content_tags`（内容-标签关联表）
多对多关系：一篇内容可多个标签，一个标签可关联多篇内容。

---

## 3. 字段说明

### 3.1 表：`contents`

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| `content_type` | TEXT | NOT NULL, CHECK | 内容类型：`article` / `video` / `file` |
| `url` | TEXT | UNIQUE（可空） | 原始链接（文章或视频链接）；文件可为空 |
| `source_name` | TEXT |  | 来源名称（如公众号、网站、平台名） |
| `title` | TEXT | NOT NULL | 标题 |
| `author` | TEXT |  | 作者 |
| `published_at` | TEXT |  | 发布时间（ISO8601 字符串） |
| `raw_content` | TEXT | NOT NULL | 原始正文 |
| `cleaned_content` | TEXT |  | 清洗后的正文 |
| `one_line_summary` | TEXT |  | 一句话摘要 |
| `language` | TEXT | DEFAULT `'zh'` | 语言标识（便于多语言扩展） |
| `extra_json` | TEXT |  | 扩展字段（JSON 字符串） |
| `ingestion_status` | TEXT | DEFAULT `'new'`, CHECK | 状态：`new`/`parsed`/`summarized` |
| `created_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | 记录创建时间 |
| `updated_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | 记录更新时间 |

> 说明：SQLite 无原生 `TIMESTAMP WITH TIME ZONE`，V1 采用 ISO8601 文本。

### 3.2 表：`content_key_points`

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| `content_id` | INTEGER | NOT NULL, FK -> `contents(id)` | 关联内容 |
| `point_order` | INTEGER | NOT NULL | 观点序号（1...n） |
| `point_text` | TEXT | NOT NULL | 观点内容 |
| `created_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | 创建时间 |

> 建议业务层约束每篇内容核心观点条数为 3-7 条。

### 3.3 表：`tags`

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 主键 |
| `name` | TEXT | NOT NULL UNIQUE | 标签名（全局唯一） |
| `created_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | 创建时间 |

### 3.4 表：`content_tags`

| 字段名 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `content_id` | INTEGER | NOT NULL, FK -> `contents(id)` | 内容 ID |
| `tag_id` | INTEGER | NOT NULL, FK -> `tags(id)` | 标签 ID |
| `created_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | 创建时间 |
| (联合主键) |  | PRIMARY KEY (`content_id`, `tag_id`) | 防止重复关联 |

## 6. 如何测试数据库是否正常

### 6.1 初始化数据库
```bash
sqlite3 database/dev.db < database/migrations/001_init.sql
```

### 6.2 写入示例数据
```bash
sqlite3 database/dev.db < database/examples/sample_data.sql
```

### 6.3 结构校验
```bash
sqlite3 database/dev.db ".schema"
```

### 6.4 外键约束校验
```bash
sqlite3 database/dev.db "PRAGMA foreign_keys = ON; INSERT INTO content_key_points(content_id, point_order, point_text) VALUES (9999, 1, 'should fail');"
```

预期：报外键约束错误，说明约束生效。

### 6.5 联表读取校验
```bash
sqlite3 database/dev.db "SELECT c.id, c.title, c.one_line_summary, GROUP_CONCAT(t.name, ',') AS tags FROM contents c LEFT JOIN content_tags ct ON c.id = ct.content_id LEFT JOIN tags t ON t.id = ct.tag_id GROUP BY c.id, c.title, c.one_line_summary;"
```

## 7. 与采集模块、前端模块的接口说明

### 7.1 采集模块 -> 数据库模块

采集模块落库时建议最小字段：
- `content_type`（默认 `article`）
- `url`
- `source_name`
- `title`
- `author`
- `published_at`
- `raw_content`

处理模块（二次处理）补充字段：
- `cleaned_content`
- `one_line_summary`
- `content_key_points`
- `tags`

建议流程：
1. 采集模块先写 `contents`（`ingestion_status='parsed'`）
2. 提炼模块更新 `cleaned_content` / `one_line_summary`
3. 提炼模块写入 `content_key_points`（3-7 条）
4. 标签模块 upsert `tags` + 写 `content_tags`
5. 最终更新 `ingestion_status='summarized'`

### 7.2 前端模块 -> 数据库模块

前端常用查询接口（可由后端 API 实现）：
- 列表页：按 `published_at` 或 `created_at` 倒序分页读取 `contents`
- 详情页：`contents` + `content_key_points` + `tags`
- 标签筛选：通过 `content_tags` 反查 `contents`
- 全文搜索（V1 可选）：对 `title/cleaned_content/one_line_summary` 做 `LIKE` 查询（后续可升级 FTS5）

## 迁移到 PostgreSQL 的建议

1. **主键策略**：
   - SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` -> PostgreSQL `BIGSERIAL` 或 `GENERATED BY DEFAULT AS IDENTITY`。
2. **时间字段**：
   - 将 TEXT 时间迁移为 `TIMESTAMPTZ`。
3. **JSON 扩展字段**：
   - `extra_json` 从 TEXT -> `JSONB`，并加 GIN 索引。
4. **标签去重**：
   - 保留唯一约束，使用 `INSERT ... ON CONFLICT DO NOTHING`。
5. **并发与事务**：
   - PostgreSQL 下为多写并发优化事务粒度；对批量入库使用批处理。
6. **检索增强**：
   - 从 `LIKE` 迁移到全文检索（`tsvector`）或外部搜索引擎。
7. **迁移工具**：
   - 推荐引入统一 migration 工具（如 Alembic/Flyway/Goose/Prisma Migrate），保持双库可追踪 schema 版本。

## 你下一步接入文章采集模块的建议

1. 采集完文章后，先把基础字段写入 `contents`（至少 URL、标题、raw_content）。
2. 以 `contents.id` 作为后续摘要/标签/观点写入的唯一关联键。
3. 清洗与摘要流程完成后，更新 `contents.cleaned_content`、`contents.one_line_summary`。
4. 将 3-7 条核心观点写入 `content_key_points`（按 `point_order` 递增）。
5. 标签先 upsert 到 `tags`，再写 `content_tags` 关联。
6. 全部完成后将 `ingestion_status` 更新为 `summarized`。
